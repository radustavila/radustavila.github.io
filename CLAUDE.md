# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Single-page personal portfolio for Radu-Adrian Stavilă, built with Astro 5 as a fully static site and deployed to GitHub Pages at <https://radustavila.github.io/>. No backend, no third-party services or trackers; fonts are self-hosted via `@fontsource-variable/*`.

## Commands

Node.js 20+ required (CI uses Node 22).

```bash
npm run dev       # dev server on http://localhost:4321 (also defined as "portfolio-dev" in .claude/launch.json)
npm run build     # static build into dist/
npm run preview   # serve dist/ locally
npm run assets    # regenerate public/og.png, favicon.png, apple-touch-icon.png
```

There is no test suite, linter or formatter configured. `npm run build` is the correctness check (TypeScript uses `astro/tsconfigs/strict`).

## Architecture

- **Content vs. presentation split.** All text, links, stats, projects, experience and skills live in `src/data/portfolio.ts`. Components in `src/components/` only render that data. Content edits belong in the data file, not in components.
- **Content must be truthful.** The data file is sourced from the CV — do not invent or embellish facts, metrics or roles.
- **Page composition.** `src/pages/index.astro` stacks the section components inside `src/layouts/Base.astro`. `Base.astro` owns all `<head>` metadata (SEO, Open Graph/Twitter, JSON-LD `Person` schema built from `profile`/`links`), imports `global.css`, and runs the scroll-reveal script.
- **Client JS is minimal and vanilla**, in component `<script>` blocks hooked via `data-*` attributes:
  - `Base.astro`: adds `.js` to `<html>` and reveals `[data-reveal]` elements via IntersectionObserver (reveal CSS is scoped under `.js` so content is visible without JS; respects `prefers-reduced-motion`).
  - `Header.astro`: mobile menu (`data-menu-toggle`/`data-nav`, breakpoint 760px), scrolled state, and scroll-spy that sets `aria-current` on nav links whose `data-nav-link` matches a section id. Section ids must match the `nav` entries in `portfolio.ts`.
  - `Projects.astro`: "Show more" toggles (`data-more-toggle`) and the interactive number-picker demo (`data-picker`).
  - `Showcase.astro`: screenshot carousel (`data-showcase`).
- **Project visuals.** A project's `visual` field is either a code-drawn illustration variant (`'migration' | 'ble'`, rendered by `ProjectVisual.astro`; a new one means extending that union and the component) or `{ screenshots }`, rendered by `Showcase.astro` — a carousel ported from the Xpiry website (stacked deck ≥901px, swipeable snap strip below; autoplay, dots, arrows). Screenshot files live in `public/images/xpiry/`.
- **Styling.** Design tokens (colours, fonts, spacing) are on `:root` in `src/styles/global.css`; component-specific styles are scoped `<style>` blocks in each `.astro` file.
- **Raster assets** in `public/` are generated by `scripts/generate-assets.mjs` (uses `sharp`, available transitively via Astro). The OG image text (name, role, stack line) is hard-coded in that script, so update it when `profile` changes, then run `npm run assets`.

## Conventions

- External links use `target="_blank" rel="noopener"`; `mailto:` and in-page anchors do not.
- Internal URLs go through `import.meta.env.BASE_URL`. The site is served from the domain root (no `base` in `astro.config.mjs`); if ever moved to a project repo, set `base` and update the absolute URLs in `public/robots.txt` and `public/sitemap.xml` (both are static, hand-maintained files).

## Deployment

`.github/workflows/deploy.yml` builds and publishes `dist/` to GitHub Pages on every push to `main`. Pushing to `main` deploys to production.

## Privacy

The repository is public. `docs/` (source CV and working notes) and all `*.pdf` files are git-ignored and must never be committed — the CV contains private contact details. The résumé button intentionally links to LinkedIn rather than a PDF for this reason.
